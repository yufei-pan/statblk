## 2026-11-14 statblk 1.62: a copy you carry is no requirement
- Changed: statblk's package metadata requires no multiCMD (`install_requires` drops `multiCMD>=1.56`). statblk runs the multiCMD it embeds (1.67 in 1.62) wherever the installed one is older than that copy, missing, or does not import, and an installed one at least as new, as before.
- Why we had to change: the floor (1.56) was below the copy statblk uses (1.61 in 1.61), so the requirement guaranteed nothing statblk relied on; it only made pip install or upgrade a multiCMD that statblk then passed over. And pip 9.0.3 (stock on EL7 and EL8) upgrades every requirement under `-U`, which stopped the install: with multiCMD 1.55 or 1.57 installed, `pip install -U statblk==1.61` exited 2 with `configparser.DuplicateOptionError` (those versions' `mcmd`, `multicmd` and `multiCMD` entry points, which pip 9 reads as one name). Without the requirement, pip 9.0.3 upgrades 1.61 to 1.62 there (exit 0, multiCMD left as it was, statblk running its embedded 1.67), and with multiCMD 1.67 installed statblk imports that one (the CI's python:3.6 image, 2026-11-14). hpcp dropped its requirement for the same reason in 9.89; the user chose "Drop it, as hpcp did (Recommended)".
- Original design was wrong because: the requirement dates from when statblk needed an installed multiCMD; once statblk carried its own copy and chose between the two by version at import, it stated no need, and a requirement that states no need still hands the installer's own failures to every install.
- Lesson: declare as a requirement only what the program needs from outside it. A library it carries a copy of and picks by version at import is not one.

## 2026-11-14 statblk 1.62: a source the timeout cut is named, and a check it hid is unknown
- Changed: `get_macos_diskutil_info()`, `parseMount()` and `get_drives_info()` take `cut`, a list that gets the name of each command `--timeout` stopped before it finished: `diskutil` and `mount` on macOS (multiCMD's return code 124), `lsblk` on Linux (124, or still running at the refresh's deadline, when a column it fills without a full fallback is collected). `main()` prints one line per command on stderr, after the table or JSON, once per run in `-w`: what stopped it and what it leaves missing (`CUT_WHAT`). In `--check`, a cut makes a run with no problem unknown (exit 3) where it can hide what the check reads, by blanking a cell it fills (`mount`: FSUSE%) or dropping a row it decides, with the row's columns: `mount`'s list with `-M` (FSUSE% and SMART), `diskutil`'s SIZE and, with `-F`, `lsblk`'s FSTYPE (SMART only, since an unmounted row has no FSUSE%; `-M` drops those rows anyway), and each of the three with a pattern that is not `-D`; any other cut does not count. In `--check` the lines are printed only when the run exits 1 or 3, so a healthy `--check` stays silent as in 1.61 (a plain run prints them every time).
- Why we had to change: 1.61 read the output of `diskutil info -all` and macOS's `mount` and dropped their exit status, so a command cut by `-t` left columns, or whole rows, blank, with nothing on stderr and exit 0. `statblk --check` then printed nothing and exited 0, which reads as healthy: the filesystems `mount` did not list were never checked, and on macOS an unmounted disk has its SIZE only from `diskutil`, so one `diskutil` stopped before it was dropped, with its SMART, before the check judged it. On the test Mac `-t 0.5` blanks MODEL on five rows. Found by the 1.61 final review and deferred to 1.62; `lsblk`'s join at the deadline had the same silence on Linux.
- Original design was wrong because: it treated a command's output as its answer, and a cut answer is not a short one; `--check`'s exit 3 existed so that "not checked" never looks like "healthy", but only SMART fed it.
- Lesson: read the exit status of every command whose output fills the result; name a source that was cut short where the operator reads, with what it leaves missing, and let a health check count what the cut could hide from it as "could not tell", while a cut that hides nothing it reads leaves a healthy run's answer and silence as they were.

## 2026-11-16 statblk 1.63: a filter drops a row only on a value that was read
- Changed: `get_drives_info()` no longer drops a row on a value it never read, in the cases below (the 1.64 entries in `docs/limitations.md` finish it: a source that failed without being stopped, and a Linux size or stat that reads as 0, still hide a row). On macOS a device `diskutil` gave no size is listed with SIZE blank (a size read as 0 still hides it); `-F` drops an unmounted device for a blank FSTYPE only when that type's source answered in full (Linux: `lsblk` exited 0; macOS: `diskutil` exited 0, `mount` was not stopped, and `diskutil` described the device); `-A` drops nothing on macOS, where throughput is never read; a mount whose `statvfs` fails keeps its row with SIZE blank and FSUSE% `ERROR` (as a hang shows `TIMEOUT`), which `--check` counts as unknown. `--check`'s rule for a command `--timeout` stopped, in `main()`, shrinks from a table of what each command can hide to two terms: `mount`'s list of mounted filesystems (FSUSE%, and with `-M` the rows), and a pattern (not `-D`), which can match any cell a stopped command fills.
- Why we had to change: the 1.62 rule predicted in `main()`, from the flags, which rows `get_drives_info()` would drop when a command was stopped. Each review of it found one more drop the prediction missed (a zero size, a blank FSTYPE, a mounted row falling to the unmounted branch, `-o` naming no `diskutil` column), and the same drops hid a failing disk from `--check` with exit 0 when nothing was stopped at all. Run on the real `main()` with faked commands (41 cases, and the test Mac's own output stopped after each of its lines), every failing disk 1.62 hid by a value it never read now exits 1 in those cases (the exceptions: a whole disk of size 0, a known limitation, and `-M` with a stopped `mount`, which exits 3; the 1.64 entries in `docs/limitations.md` list the other places where a source that failed without being stopped, or a size read as 0, still hides a row), a healthy run with a stopped `diskutil`, or a stopped `lsblk` with `-F`, exits 0 where 1.62 gave 3, and no case moves from 1. A 0 can become 3: a disk 1.62 did not list is now judged, and exits 3 when its SMART cannot be read.
- Original design was wrong because: a value that was never read (`diskutil` not run, stopped, or silent on a device; `lsblk` missing or stopped) was taken as 0 or blank, and a filter dropped the row on it. The cut table was then a second code path guessing those drops, and it could only fall behind the first.
- Lesson: a filter drops a row only on a value that was read; a value whose source did not answer keeps the row, its cell blank. A check over the rows then needs no second path predicting what the filters hid, beyond the two facts the rows cannot show (what `mount` listed, and what a pattern would have matched in a cell a stopped command fills). 1.63 applies it to a stopped or missing command and to `statvfs`; the 1.64 entries in `docs/limitations.md` finish it.

## 2026-11-20 statblk 1.64: not answering is one state, whatever the cause
- Changed: `get_drives_info()` keeps one record, `unanswered`, of each command that did not answer in full (`lsblk`, macOS's `diskutil` and `mount`), with its exit status: 124 stopped by `--timeout` (or still running at the deadline), 127 not found, any other a failure. `--check`'s rule and the stderr note read it; `main()`'s `shutil.which('lsblk')`, its separate "lsblk not found" note, and `get_macos_diskutil_info()`'s `failed` list are gone. A missing or failing command now counts in `--check` as a stopped one did: a healthy run exits 3 where 1.63 gave 0 when macOS's `mount` fails, and with a pattern (not `-D`) when `lsblk` or `diskutil` is missing or fails; the note says "not found" or "failed (exit N)". `diskutil` and `mount` are found in the sbin directories too. 1.63's other half, "a filter drops a row only on a value that was read", is finished in the same version: a sysfs size or stat that cannot be read, and macOS's throughput, are None, not 0, so the row stays with the cell blank (`null` in `-J`); `-A` drops only a device read as idle, keeps the `-P` rows, and keeps a mount that failed. The record and the note exist only when a collected column needs the command (`lsblk`: FSTYPE, UUID, MODEL or SERIAL, or `-F`); `-F`, `-A` and the size filters keep a row whose value was not read, while a pattern is matched against what was read.
- Why we had to change: 1.62 learned to read the exit status of the commands whose output fills the table, but only for one status, 124. A missing `lsblk` was found by a separate `which()` in `main()` with its own note and its own rule (shown columns only: an `-o` without FSTYPE hid it, even with `-F`); a failing `diskutil` went to a third list that only `-F` read; a failing macOS `mount` was not recorded at all. Each was a way not to answer that the check did not see: `statblk --check ext4` on a host without `lsblk` exited 0 over a failing disk whose only `ext4` came from `lsblk`, and on macOS a `mount` that failed (or was not found, as under cron, whose `PATH` lacks `/sbin`) exited 0 over a full filesystem.
- Original design was wrong because: the record was named for one cause ("cut") and each new cause got its own path, so every reader had to know every path, and none did. The causes differ only in the sentence on stderr; what they leave unread, and so what the check cannot tell, is the same.
- Lesson: record "did not answer" once, at the read, with the source's own status, and derive every consequence (rows kept, an unknown exit, the note's wording) from that record; a value from a source that did not answer is "not read", never 0 (its cell is blank).
